# Upscaly Deep Audit — 2026-08-15

Branch: `refactor/modularization` · ~11,200 LOC (7.0k TS/TSX, 4.2k Rust)
Method: 5 parallel audit passes (backend correctness, pipeline performance, frontend, architecture, QA toolchain) + full toolchain run.
Interactive report: published as a Claude Artifact (see conversation).

Upscaly is in better shape than most Tauri apps its size — the process runner is properly
abstracted, pipes are drained, argument passing is shell-safe, the VRAM governor is genuinely
well-tested, and event-listener hygiene is textbook. But "every feature works" is not true on
this branch: **batch mode is unreachable, model download progress never renders, and one
critical path-traversal bug can recursively delete arbitrary directories.** Totals: 4 critical,
12 high, ~18 medium, plus ~1.5–2.5× video throughput headroom on mainstream GPUs.

## Why green tooling hid this
- **Lint gate neutered.** `src-tauri/src/lib.rs:1` has `#![allow(clippy::all, clippy::pedantic, …)]`,
  cancelling the `[lints]` policy in `Cargo.toml`. Clippy's "zero warnings" means nothing.
- **Tested state machine isn't the running one.** `src/lib/jobState.ts` is imported only by its
  own tests; production handlers do ad-hoc string checks.
- **Nothing tests the wiring layer.** No test renders `useStudioContainerSetup`, the spread-merge
  composition root where the batch bug lives.

## Critical
1. **Arbitrary recursive directory deletion via frontend-controlled job id.**
   `video_pipeline/context.rs:44-51`, `commands/upscale.rs:9`. Webview `job_id` is spliced into
   `cache_dir\upscaler_job_{id}` and passed to `fs::remove_dir_all` (twice). `..\..\..\...` escapes
   the cache dir. Fix: backend-generated ids + canonicalize-and-assert child-of-cache before delete.
2. **Batch mode unreachable — two `batchItems` stores, populated one shadowed.**
   `useMediaSelection.ts:44` fills one store; `useUpscaleQueue.ts:47` owns a second empty one;
   `useStudioContainerSetup.ts:140-148` spreads `batch` last so the empty copy wins. Fix: one owner,
   explicit named exports instead of the six-object spread.
3. **Rules-of-Hooks violation crashes the queue when it first fills.**
   `BatchQueueView.tsx:78-83` — `return null` sits above 4 hook calls. Masked only because #2 keeps
   items empty. Fix: hooks above the early return.
4. **Batch runs can't be cancelled and never report completion.**
   Queue `activeJobId` never exposed (`useBatchSetup.ts:90-96`); `onCancelItem` never wired;
   `runNextInQueue`/`pendingQueueRef` dead; `isBatchRunning` never cleared. Fix: cancel by item
   job-id end to end; drive completion off terminal events.

## High
- **Lost-wakeup race** `job_queue.rs:159-182` — enqueue as the worker exits → job stuck queued forever.
- **Pipeline errors orphan the ffmpeg extractor** `phases.rs` (210/256/389) — leaks GB; temp dir can't
  be deleted while ffmpeg writes into it.
- **Mid-extraction failure ships a truncated video as "Succeeded"** `phases.rs:164-174` — error only
  surfaced if zero frames exist; `-shortest` hides the mismatch.
- **No disk-space check before extracting tens of GB** — `get_available_disk_space` +
  `InsufficientStorage` both exist as dead code.
- **`assetProtocol` scope `"**"`** `tauri.conf.json:24-27` — webview can read any file; `open_file_native`
  runs arbitrary paths via `cmd /c start`.
- **Model downloads: no progress, no SHA-256 check** — only emitter is dead code; live path skips the
  hashes sitting in the registry.
- **Completion race stamps old job's output onto newly selected file** `studioJobHandler.ts:37-58`.
- **Side effect inside setState updater → duplicate history under StrictMode** `useUpscaleQueue.ts:203-205`.
- **Toasts never expire; dedupe swallows future notifications** `useStudioState.ts:34-44`,
  `ToastContainer.tsx:19`.
- **Settings save-effect races load and clobbers prefs** `useSettings.ts:49-109` — hardcoded
  `auto_check_updates`, mute dual-store drift.
- **Drag-and-drop advertised, not implemented** — no `onDragDropEvent` anywhere.
- **Escape instantly kills an hour-long job, bypassing the confirm dialog** `useKeyboardShortcuts.ts:49-52`.

## Medium (selected)
Cancel race window (`job_queue.rs:101-139`); Unix signal-killed child maps to "still running"
(`process_runner.rs:38-46`); hung ffprobe wedges the serial queue (`phases.rs:491-506`); GPU probe
pipe deadlock + uncached negatives → repeated 5s stalls (`sidecar_manager.rs:255-291`); `wmic` VRAM
fallback caps at 4GB / gone on Win11 (`job_queue.rs:366-384`); VFR A/V desync (`phases.rs:40`,
`encoder.rs:40`); odd dimensions fail every encoder (`encoder.rs`); AUTO tile has no OOM retry
(`phases.rs:361`); batcher renames the frame ffmpeg is still writing (`phases.rs:219`); whole-app
re-render per progress tick (no `React.memo`, 60ms emit loop); late events resurrect terminal items
(`useUpscaleQueue.ts:170`); fabricated titlebar VRAM meter (`useTelemetry.ts:23`); `BatchQueueRow`
renders `file.name` but items set `fileName`; slider drag lacks pointer capture/RAF; one stalled
`getMediaDimensions` blocks a multi-open (`media.ts:23`); `model-catalog-updated` has no listener.

## Low
No `CREATE_NO_WINDOW` on spawns (console flashes); non-atomic settings write + silent reset;
dialog/focus a11y; Google Fonts vs offline claim; DXGI adapter picks wrong GPU on dual-AMD;
`kill_all_processes()` operates on an empty registry.

## Architecture diagnosis
God component → god hook: `useStudioContainerSetup` returns ~70 identifiers via six spreads whose
ordering silently resolves collisions (root cause of the batch bug). Domain logic duplicated across
the IPC boundary and drifting: model catalog (4 copies, names already disagree), output paths (4,
three naming schemes), scale parsing (2), VRAM/tile (3 backend + 1 fake UI), status vocabulary (2
alphabets), ETA math (2). Backend queue is the real state machine but write-only telemetry — no
snapshot command, so the frontend rebuilds from the event stream across four parallel stores and
seeds optimistic states. 13 of 27 commands dead. Typed `AppError` exists but every command returns
`String` with `"cancelled"` as control flow. No CI.

## Status (updated after the remediation pass)

Everything in Critical, High, Medium and Low above is fixed, plus P1/P2/P4–P10.
Guardrails are in place: Windows CI runs the full suite on every push, clippy
runs with `-D warnings`, and the IPC types are generated from the Rust structs
(`npm run gen:types`) with CI failing on drift.

Still open, and deliberately so — these three are one interlocking change, not
three independent ones:

- **P3 (folder-mode image batches).** Needs per-item cancellation and error
  attribution across a single shared NCNN process, which the current
  one-Job-per-image model cannot express. Blocked on Phase 4.
- **Phase 4 (backend job store).** `job_store.rs` with validated transitions,
  `get_jobs_snapshot()`, coalesced deltas, `AppError` end to end.
- **Phase 5 (collapse hooks layer).** Depends on Phase 4's snapshots; there is
  no green intermediate state between them.

Two carry-overs worth knowing:

- **P5 (streaming reassembly) is field-verified.** A 720x1280 clip upscaled
  4x to 2880x5120 on an RTX 3050 6GB: correct dimensions, full duration,
  audio in sync, plays normally. The same run also confirmed the collision
  suffix from the path-ownership change (`..._upscaled_4x (1).mp4`, not the
  doubled `..._upscaled_4x_4x (1).mp4` the old code produced) and that the
  VRAM estimator's projection (2.3GB) matches actual usage (2.0GB dedicated).
  Not exercised: the odd-dimension pad filter, since 720x1280 scales to even
  dimensions at every supported factor. It is unit-tested and cannot misfire
  on even input, but treat it as untested in the field.
- **P1 is half-landed by design.** Batch pre-staging is done; concurrent
  pre-spawn is not, because two NCNN processes exceed the governor's own
  ceiling wherever it selects dual-proc (12GB/512px wants ~14.4GB against a
  9.2GB budget), so it would only ever apply where the profile is already
  single-threaded.

## The plan (7 phases, each shippable)
- **Phase 0 — Safety & correctness hotfixes (M, ship first):** all four criticals + queue integrity
  + pipeline honesty + security scoping + model integrity + UX races.
- **Phase 1 — Performance quick wins (S–M):** P1+P2 (the 1.5–2.5×), P4, P7–P10, `CREATE_NO_WINDOW`.
  Benchmark on 6GB + 8GB GPUs.
- **Phase 2 — Delete dead surface (S):** 13 commands, duplicate catalogs/path builders, fake
  telemetry, unused deps; remove `#![allow(clippy::all)]` and fix findings.
- **Phase 3 — Single source of truth (M):** backend owns catalog, paths (`run_upscale` returns the
  reserved path), VRAM; history stores `modelId`; one status vocabulary.
- **Phase 4 — Backend-owned job store (L, core move):** `job_store.rs` validates transitions, exposes
  `get_jobs_snapshot()`, emits coalesced deltas (kills the 60ms flood); `AppError` end to end.
- **Phase 5 — Collapse hooks layer (M):** one sliced store mirroring snapshots; delete
  `useStudioJobStateSetup`, ref-cycle hacks, setter bags, optimistic writes; `React.memo` leaves.
- **Phase 6 — Pipeline v2 + guardrails (L):** streaming encode, backpressure, VFR, pad filter,
  folder-mode images; video-pipeline + cancellation + container-integration tests; **generated TS
  types from Rust (specta/ts-rs)** to kill the drift class; Windows CI.

## Verified non-issues
Shell-safe argument passing; main runner drains pipes with a capped ring buffer;
`reserve_output_path` never deletes user files; VRAM governor MB math consistent; lock ordering
unidirectional; Windows-safe model renames; textbook `useJobEvents` cleanup; singleton
`AudioContext`; history capped at 20.
